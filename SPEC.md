# ТЗ: уведомлялка о слотах BLS (Португалия)

Это ТЗ для Claude Code на локальной машине. Вставьте его целиком первым сообщением.

## Что делаем и чего не делаем

Бот раз в 10–15 минут открывает страницу записи BLS в уже залогиненной сессии. Если появились слоты, он шлёт сообщение в Telegram. Записывается человек сам, руками.

Запрещено (это часть требований, а не пожелание):
- нажимать кнопки записи, отправлять формы, выбирать даты или слоты;
- решать капчу любым способом, включая сторонние сервисы;
- логиниться автоматически: логин и капчу проходит человек;
- маскировать автоматизацию (stealth-плагины, подмена fingerprint), ротировать прокси или IP;
- держать больше одной сессии, одного аккаунта или одной вкладки;
- проверять чаще одного раза в 10 минут;
- читать Telegram-чаты и каналы. Источник данных только сайт BLS.

## Стек

- Node.js 20+, TypeScript, `pnpm` или `npm`.
- Playwright (`chromium.launchPersistentContext`) с постоянным профилем в `./.profile`, чтобы сохранялась сессия после ручного входа.
- Telegram Bot API через обычный `fetch` (`sendMessage`, `sendPhoto`). Отдельная библиотека не нужна.
- Тесты: `vitest`.
- Конфиг через `.env` (пример в `.env.example`, сам `.env` в `.gitignore`):
  - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`;
  - `BLS_URL`: страница, где видно наличие слотов (заполнит пользователь);
  - `TZ` (например `Europe/Moscow`);
  - `WINDOW_DAYS=17-28`, `INTERVAL_MIN=10`, `INTERVAL_MAX=15`;
  - `HEARTBEAT_AT=09:00`.

## Команды

1. `npm run login`: открывает видимый браузер на `BLS_URL` с профилем `./.profile`. Человек входит и проходит капчу, потом нажимает Enter в терминале. Скрипт проверяет, что страница выглядит залогиненной, и закрывается.
2. `npm run snapshot -- <label>`: одна проверка в текущей сессии. Сохраняет `fixtures/<label>-<timestamp>.html` и `.png`. Нужна для сбора снимков под тесты.
3. `npm run watch`: основной цикл (ниже).
4. `npm test`: тесты парсера на снимках.

## Порядок работы (строго по шагам)

### Шаг 1. Снимки и разведка
- Сделать `login`, затем `snapshot no-slots`.
- Изучить реальный HTML и найти устойчивые признаки состояний:
  - «слотов нет» (текст сообщения, отключённый календарь и т. п.);
  - «сессия истекла» (редирект на логин, форма логина, капча на странице);
  - «слоты есть».
- Для «сессия истекла» снимок можно получить, выйдя из аккаунта или подождав истечения сессии.
- **«Слоты есть» сейчас снять нельзя.** Признак описать как гипотезу, пометить в коде комментарием `UNVERIFIED` и в README. Снимок `available` сделать в первый день раздачи и после этого поправить парсер.

### Шаг 2. Парсер
Чистая функция без Playwright:

```ts
type Status =
  | { kind: 'none' }
  | { kind: 'available'; details?: string }
  | { kind: 'session_expired' }
  | { kind: 'unknown'; reason: string };

function parseAvailability(html: string, url: string): Status;
```

- Тесты на каждом снимке из `fixtures/`.
- Всё, что не распознано уверенно, возвращает `unknown`, а не `none`. Молча считать «слотов нет» нельзя.

### Шаг 3. Цикл `watch`
- Работает только в дни из `WINDOW_DAYS` по `TZ`. Вне окна спит до начала окна (раз в сутки пишет в лог).
- Интервал: случайный от `INTERVAL_MIN` до `INTERVAL_MAX` минут. Одна вкладка, `page.goto(BLS_URL)` или `reload`, без кликов.
- Таймаут навигации 60 с. Ошибка сети — запись в лог и повтор на следующем тике. После 3 ошибок подряд — сообщение в Telegram.
- Реакция на статус:
  - `available`: сообщение со ссылкой `BLS_URL`, текстом `details` и скриншотом. Повтор не чаще раза в 20 минут, пока статус держится.
  - `session_expired`: одно сообщение «Сессия слетела, запустите `npm run login`». Проверки останавливаются до повторного логина (бот ждёт, пока появится маркер-файл от `login`, или перезапуска).
  - `unknown`: сообщение со скриншотом и `reason`, не чаще раза в час. Снимок HTML сохраняется в `fixtures/unknown-*` для разбора.
  - `none`: только запись в лог.
- Heartbeat раз в сутки в `HEARTBEAT_AT`: «Жив. Последняя проверка: <время>, статус: <статус>, проверок за сутки: N». В дни вне окна тоже, с пометкой «вне окна».
- Состояние (последний статус, время последних уведомлений) хранить в `state.json`, чтобы после перезапуска не было дублей и ложных heartbeat.
- Корректное завершение по SIGINT/SIGTERM: закрыть браузер, отправить «Остановлен».

### Шаг 4. Запуск постоянно
- README: как запускать на macOS через `launchd` (plist с `KeepAlive`) или `pm2`.
- Предупредить, что Mac не должен засыпать (`caffeinate -s` или настройки энергосбережения), иначе бот молчит. Это ловит heartbeat.
- Проверить сценарии: перезапуск, слетевшая сессия, нет сети.

## Критерии готовности
- `npm test` зелёный на снимках `no-slots` и `session-expired`.
- Тестовое уведомление приходит в Telegram (`npm run watch -- --test-notify`).
- Слетевшая сессия даёт одно сообщение, а не поток.
- Heartbeat приходит ежедневно.
- В README отмечено, что признак «слоты есть» не проверен, и описано, как его уточнить.

## Открытые вопросы к пользователю
- Точный `BLS_URL` страницы, где видна доступность.
- Часовой пояс и время heartbeat.
- Нужен ли второй получатель уведомлений (например, отдельный чат).
